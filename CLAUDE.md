This file covers every project in the repository. The parent file `~/dev/CLAUDE.md` holds rules for a
different project (DiffPrior) and does not apply here.

## Shared rules

- **Git.** Never run `git commit`, `git push`, `git reset`, `git rebase` or any history rewrite. Stage by
  explicit path only, never `git add .` or `-A`. At the end of a unit of work, print the exact
  `git add` and `git commit -m` blocks for the owner to run, each followed by the test command to
  run after it. Conventional prefixes (feat, fix, docs, data, chore). No AI attribution anywhere.
- **Spend.** OpenAI spend across the whole repository is capped at $25, counting `results/calls.jsonl`
  and `results/itemtriage/calls.jsonl`. Print a cost projection before any API pass, and run a
  300-item pilot before any full pass. Stop and report if a projection or the running total would
  exceed the cap.
- **Intervals.** Every reported number carries an interval: 2000-resample bootstrap with seed 42,
  paired bootstrap for differences between scorers, Wilson for proportions. Raw counts carry none.
- **Label isolation.** Scorers never read labels. Labels join only in evaluation, calibration of
  supervised tiers, and gates.
- **Ties.** In new code, ties in any ranking are broken by a declared secondary scorer, never by
  row or qid order. Routing's existing scorers keep qid tie-breaks (ADR-020).
- **No thresholds in config.** Cutoffs exist only as calibration outputs with file hash and n.
- **Caching.** Every raw model response (API JSON, local logits) is cached so all downstream
  numbers regenerate on CPU without new calls.
- **Determinism.** The routing report, `results/evaluation.json` and `HANDOFF.md` are byte-identical
  on rerun. CI checks this. `HANDOFF.md` is generated by `scripts/fill_handoff.py` and is never
  edited by hand.
- **Prose.** No em dashes in prose, code comments or docs. Short plain sentences.

## Running things

```bash
python3 -m routing.cli score --split calibration && python3 -m routing.cli score --split test && python3 -m routing.cli gates && python3 -m routing.cli calibrate && python3 -m routing.cli evaluate && python3 scripts/fill_handoff.py
python3 -m pytest tests --ignore=tests/hv2 --ignore=tests/itemtriage   # routing and v1, with PYTHONPATH=packages/halluscope-core/src
python3 -m pytest tests/itemtriage
.venv/bin/python -m pytest tests/hv2 -m "not slow"
```

GPU work runs in `.venv` under `src/hv2/gpulock.py`'s `GpuLock`, one CUDA process at a time, on an
RTX 3060 with 6 GB. CPU-only commands set `CUDA_VISIBLE_DEVICES=` so they never touch the GPU.

## hv2 study rules

These are the original hv2 rules, unchanged. They apply to `src/hv2/` and its runners.

### Mission
NeurIPS/ICML-grade study: which hallucinations are detectable from
(a) text only, (b) top-k logprobs, (c) full output distribution, (d) hidden states.
Core hypothesis: on the "knows-but-hallucinates" (KH) stratum, (a)-(c) ≈ chance,
(d) ≫ chance. On "doesn't-know" (UH), all work. E3 two-sample test certifies this.

### Hardware constraints (HARD RULES)
- Single RTX 3060 Laptop, 6GB VRAM. ONE GPU process at a time, ever.
  Acquire ./gpu.lock (create file with PID) before any CUDA work; delete after.
  If lock held, do CPU work or wait. Never kill another process's lock.
- Models: Qwen/Qwen2.5-0.5B-Instruct (smoke tests ONLY),
  Qwen/Qwen2.5-1.5B-Instruct (fp16), Qwen/Qwen2.5-3B-Instruct (4-bit NF4
  via bitsandbytes). batch_size<=4, max_new_tokens<=48, torch.inference_mode().
- NEVER store full-vocab logits. Per token store: top-100 logprobs + scalar
  functionals (entropy, energy=-logsumexp, top1-top2 margin) computed online.
  Hidden states: all layers, float16, ONLY at key positions (last prompt tok,
  first/last answer toks, exact-answer toks). Cache to data/cache/*.h5.
- Disk budget 60GB. Check `df -h` before big writes.

### Scientific integrity (HARD RULES)
- Fixed seeds (42/43/44). Splits: calib/val/test disjoint by QUESTION, created
  once in e1, hashed, never modified. No test-set peeking, no threshold tuning
  on test. Every number in reports must be regenerable by a script in scripts/.
- Never fabricate, interpolate, or "estimate" results. If a run fails, report
  the failure. Bootstrap CIs (1000 resamples) on every AUROC.
- Exact-match grading uses TriviaQA alias lists + normalization (lower, strip
  articles/punct). Log 50 random grading decisions per run for human audit.

### Conventions
- Python 3.11, uv venv. Deps: torch (cu121), transformers, bitsandbytes,
  datasets, accelerate, scikit-learn, h5py, numpy, pandas, matplotlib, scipy.
- Code in src/hv2/, runnable scripts in scripts/, configs in configs/*.yaml,
  results in results/<exp>/<timestamp>/ with config snapshot + git hash.
- Long runs: resumable (per-example checkpointing to the h5 cache), tqdm to
  logs/<exp>.log, append-only.
- Commit per milestone, conventional messages, never push, never force ops.
- If blocked >20 min on anything, write BLOCKERS.md and move to next task.
- End-of-session: update REPORT.md (what ran, numbers w/ CIs, what's queued).

### Strata definitions
KH = model answered correctly on >=6/8 neutral probes but wrong under
perturbation. UH = wrong on >=6/8 probes and wrong in main generation.
KC/UC analogous. Perturbation bank (record type as covariate): (P1) prepend
plausible-but-wrong context sentence, (P2) 4-shot prompt w/ 2 wrong exemplars,
(P3) format pressure ("answer with name only, you must answer").
