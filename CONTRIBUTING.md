# Contributing to HalluScope

## Branches

- **`main`** — integration branch. The pre-`feature/full-pipeline` state is tagged
  by the commit `checkpoint: pre-routeB working tree`.
- **`feature/full-pipeline`** — active development of the full multi-stage pipeline
  (Stage 1 prompt-risk, Stage 2 internal signals, Stage 3 semantic checks),
  fit-from-data HRI weights, deterministic eval, baselines, and ablation.

### Stale branches — do not build on these

- **`origin/feature/combined`** — **superseded / abandoned.** It contains *no*
  commits that are not already on `main` (`git log main..origin/feature/combined`
  is empty); it is an older pre-refactor snapshot. Do **not** branch from it or
  merge it. It is being left in place rather than force-deleted to preserve remote
  history; treat it as read-only archaeology.

## Environment & vendored directories

`frontend/node_modules/` and `backend/.venv/` were previously committed by mistake.
They are now untracked (still in `.gitignore`) but remain on disk. Re-create them with:

```bash
cd frontend && npm install
cd backend && python3 -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt
```

## Reproducibility & results — hard rules

1. **Never commit fabricated or placeholder experimental numbers.** Code builds
   *capability*; a human runs the experiments and records the real outputs. Result
   files (`eval/results_*.csv`, `eval/summary.json`, ROC PNGs) are generated by
   running the documented commands, never hand-edited.
2. **All new computation must be seeded** (`backend/app/seeding.py`) and eval
   generation must default to deterministic decoding.
3. **No magic numbers.** HRI weights live in `config/weights.json`; normalization
   constants live in `config/norm.json`. `hri_engine.py` loads them — it does not
   hardcode them.
4. **Every signal has a direction unit test** under `tests/` proving that a more
   uncertain / riskier synthetic input yields a higher signal value (or documenting
   why the relationship is inverted).
